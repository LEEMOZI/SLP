SLP 法律工作台
产品架构与产品需求文档

把已有法律检索、裁判文书检索、文档解析、模型路由与交付能力，封装为以案件为中心、结论可溯源、任务可恢复、系统可持续升级的可视化产品。

Web MVP 优先Tauri 桌面版后续本地数据优先保留 MCP 高级客户端

01 背景与目标

SLP 已具备可用的事务能力，但入口分散在 DSH、Cherry Studio、WorkBuddy 等通用客户端中。用户需要理解工具名、模型名和调用顺序，案件材料、检索证据、生成内容与交付版本之间也缺少统一的可视化关系。

已确认的现状

  • 已有法规、参考案例、合同模板、业务指南和大规模裁判文书检索能力。
  • 已有文档读取、合同审查、诉讼文书生成、证据评价和结果交付能力。
  • 已有本地主力模型、复杂任务质量备用模型、视觉/英文备用模型及云端路由。
  • 已有案件标识、任务观测、长文本分段、交付校验和 launchd 常驻服务。
  • Mac Studio 承担算力与数据，MacBook 作为瘦客户端。

需要解决的产品问题

  • 从“模型调用工具”转为“用户完成法律工作”，隐藏工具编排细节。
  • 以案件聚合材料、任务、证据、摘要和交付版本。
  • 长任务可查看进度、取消、重试，部分失败不丢失已完成成果。
  • 模型生成内容与检索证据明确分离，关键结论可回到原文。
  • 程序、配置、模型与知识数据可独立升级，升级不破坏用户工作。
核心产品决策：第一版不做另一个聊天窗口，而做“案件工作台 + 统一任务中心 + 引用溯源”。通用 MCP 客户端继续保留，但不再是唯一操作入口。

产品目标

  • 用户能在一个案件内完成材料准备、法规/类案检索、研究摘要和导出。
  • 每条进入研究摘要的关键事实都能区分“检索证据”与“模型归纳”。
  • 检索超时、解析失败或服务不可用后，用户能保留输入并恢复工作。
  • 后续桌面化和版本升级不改变案件、证据与交付对象的统一含义。

02 产品契约

契约项定义
主要用户使用 SLP 的律师/法律从业者。P0 为单用户产品，不引入团队角色和跨用户权限。
核心任务围绕一个案件，获得可核验的法规与类案研究结果，并将人工复核后的内容保存或导出。
启动条件用户创建或打开案件；可直接提出法律问题，也可先上传案件材料。
完成条件研究结果已保存到案件，且导出物包含来源清单、任务信息和人工编辑后的正文。
核心共享对象案件。材料、检索任务、研究摘要和交付版本均归属于案件；跨案件的通用设置单独管理。
信任边界检索原文是证据；模型生成文字是辅助研究草稿。草稿不能直接标记为“已核验”，必须由用户确认。
恢复承诺失败任务保留输入、参数和错误；重试产生新的执行记录，不覆盖上一次结果。
[Assumption, TBD] P0 按个人本地工作台设计。若首个版本即需要多人共同编辑、客户隔离或组织权限，角色模型和案件共享流程需要重新评审。

03 版本范围

范围包含的完整能力边界
P0 · Web MVP系统就绪检查、案件管理、材料上传解析、法规/类案统一检索、任务中心、证据查看、研究摘要、保存与导出。完成“进入案件 → 获得可溯源研究 → 导出并恢复失败”的最小闭环。
P1 · 桌面工作台合同审查、诉讼文书生成、证据评价、完整交付中心、模型与路由设置、知识库和诊断界面。复用 P0 的案件、任务、证据和版本对象，不另建平行工作流。
P2 · 可分发产品安装器、服务自启、签名与自动更新、配置迁移、数据备份恢复、版本回滚。模型与知识库作为独立数据包，不随每次程序升级重复分发。
P3 · 团队能力多用户、组织权限、案件共享、集中审计和远程算力节点。只有出现真实团队使用需求后启动。

P0 不包含公网开放、多用户协作、在线支付、自动向第三方法院/客户系统提交文件，也不允许模型在无人工确认的情况下把草稿标记为最终法律意见。

04 产品架构

4.1 目标架构

体验层｜同一套产品行为，不同外壳

Web 工作台（P0）Tauri 桌面壳（P1）浏览器瘦客户端DSH / Cherry / WorkBuddy（高级入口）
新工作台使用统一业务接口；MCP 继续服务通用 Agent 客户端。

业务层｜面向用户对象，而非面向工具名

案件材料检索研究合同/文书任务中心证据与引用交付版本设置与审计

能力适配层｜隔离外部能力变化

法规检索适配裁判文书适配文档解析适配模型路由适配交付校验适配
业务层只理解“主力/质量/视觉”等模型角色，不直接理解某个运行时命令。

运行与数据层｜Mac Studio 算力主机

现有 SLP 核心能力本地模型运行时案件与任务数据向量知识库裁判文书库交付存储

4.2 架构决策

决策产品含义升级约束
统一业务入口工作台不依赖 MCP 工具数量或名称；检索、任务和交付对用户保持连续。业务接口版本化；旧高级客户端可继续通过 MCP 使用。
案件为聚合根任何材料、任务、摘要和交付都能回到所属案件。跨模块只使用统一案件标识，不以客户端会话作为案件真相。
模型角色化用户选择“日常/质量优先/视觉”等角色，而不是记忆模型 ID。更换 LM Studio、Ollama 或具体模型时，案件和任务记录仍保存当时实际模型快照。
数据与程序分离应用升级不重复下载模型或裁判文书库。程序、配置、模型、知识数据分别有版本和兼容检查。
证据与草稿分离原文、定位、摘录独立于模型摘要保存。模型升级不会改写已保存的证据；重新生成形成新摘要版本。
任务可恢复长检索和解析都有持久状态、阶段进度和执行记录。重试不覆盖旧执行；部分完成结果可查看、可 narrowing 后继续。

4.3 独立升级域

应用程序

工作台与业务服务可升级；升级前检查数据兼容性，失败时不启动半升级状态。

用户配置

路径、模型角色、检索偏好和交付设置随版本迁移；原配置保留可读的备份。

模型与知识数据

独立更新和校验；更新中不可用的能力明确显示，不阻断已有案件和交付读取。

回滚边界：程序回滚不得删除或降级覆盖用户案件、证据和交付文件。若新版本数据不能被旧程序读取，产品必须阻止不兼容回滚并说明所需的数据备份，而不是静默打开。

05 产品模型与核心流程

5.1 对象与状态

对象必要信息状态/规则
案件名称、案由/类型、当事人备注、创建时间、归档状态进行中 ↔ 已归档；归档默认只读，可解除归档。P0 不提供永久删除。
材料原文件名、类型、上传时间、解析状态、文本/页码可用性、来源任务待解析 → 解析中 → 可用 / 部分可用 / 失败；原文件不可被生成任务改写。
检索研究问题、范围、过滤条件、命中证据、研究摘要、保存版本一次检索可多次执行；只有用户保存后成为案件研究成果。
任务类型、所属案件、输入快照、阶段、进度、错误、执行记录排队中 → 运行中 → 已完成 / 部分完成 / 失败 / 已取消。
证据来源类型、标题、定位信息、原文摘录、所属检索执行不可被模型摘要覆盖；定位不可用时明确标注，不补造页码或段落。
研究摘要正文、引用关系、编辑状态、实际模型、生成任务、保存时间模型草稿 → 人工编辑 → 已确认；重新生成创建新版本。
交付版本正文快照、来源清单、校验结果、文件格式、创建时间导出后不可变；修改正文需创建新交付版本。

5.2 P0 核心流程

创建/打开案件确定工作上下文
→
提问或上传材料保留输入快照
→
执行检索/解析任务可见、可取消
→
查看证据回到来源与原文
→
编辑研究摘要确认引用与表述
→
保存/导出形成不可变版本

最重要的恢复路径：长检索只完成部分年份或某个服务失败时，页面保留问题、过滤条件和已返回证据，标记覆盖范围；用户可缩小范围重试，不需要重新创建案件或重传材料。

06 P0 功能需求

FR-01 系统就绪与工作台首页

目的：让用户在开始案件工作前知道哪些能力可用，避免把服务故障误解为“没有检索结果”。

  • 触发：打开工作台、手动刷新状态，或任务返回服务不可用。
  • 处理：汇总法规检索、裁判文书、文档解析、模型和交付能力的就绪状态；显示当前算力节点和模型角色，不要求用户理解端口或进程。
  • 结果：全部就绪时进入案件列表；部分不可用时允许读取已有案件和交付，但禁用依赖故障能力的新任务，并说明原因。
  • 异常：状态检查失败本身不得清空案件列表；提供重试和诊断信息入口。P0 只允许查看诊断，不提供进程自启按钮。

FR-02 案件管理

目的：把所有后续工作绑定到明确案件，避免跨会话材料混用。

  • 触发：用户创建案件、搜索/筛选案件、打开或归档案件。
  • 字段：案件名称为必填；案由/类型、当事人备注为可选。案号可在后续补充，不作为创建前提。
  • 处理：创建后进入案件工作台；列表显示名称、类型、最近活动、未完成任务数和归档状态。
  • 结果：当前案件在材料、检索、任务和导出页面保持一致；切换案件不会把上一案件的草稿自动带入。
  • 归档：归档需确认；归档案件默认可读，不可新建任务。解除归档后恢复。
  • 异常：同名案件允许存在，但列表需用创建时间区分；未保存编辑离开案件时提示保存，不静默丢弃。

FR-03 案件材料上传与解析

目的：把用户卷宗转化为可检索、可引用的案件证据。

  • 触发：用户在材料页选择或拖入文件；P0 支持 PDF、DOCX、TXT、Markdown。扫描 PDF 在 OCR 能力可用时进入解析，不可用时明确提示。
  • 处理：上传后立即显示材料记录和解析任务；计算文件指纹用于重复提醒。解析完成后记录可用文本、页码定位是否可用和失败原因。
  • 结果：可用材料可进入检索上下文；用户能查看原文/解析文本及其定位。原材料不可被后续生成任务覆盖。
  • 重复：发现相同文件时不自动合并，提示“已存在相同材料”，由用户选择仍上传或取消。
  • 异常：加密、损坏、不支持或部分页面失败时保留原文件和错误说明；部分可用材料必须标注未覆盖范围。

[TBD] 单文件大小、单案件文件数与扫描页数上限在性能验证后确定；界面必须在达到上限前说明，而不是上传后才报错。

FR-04 统一法规与类案检索

目的：用户用法律问题检索，不需要决定底层调用哪个工具。

  • 触发：在案件内输入问题并选择“自动 / 法规 / 类案”；可选择是否引用已上传材料。
  • 处理：自动模式识别检索意图；类案默认使用裁判文书来源，指导案例仅作补充。自然语言问题可转换为关键词，但页面显示实际执行的检索词，允许用户修改。
  • 过滤：类案支持年份、法院、案由；法规支持效力/主题过滤时，仅展示底层实际可用的条件，不显示无效过滤器。
  • 结果：按法规、类案、业务参考分组；显示标题、来源、关键摘录、命中原因和可用过滤条件。部分匹配必须标注，不能伪装为完全命中。
  • 证据：点击结果打开原文面板，显示已有定位信息；无页码时提供可用的案号/条款/段落定位，不生成虚假定位。
  • 空结果：说明实际检索词和范围，提供可编辑的缩减关键词建议；不得把“未命中”表述为“法律没有规定”。
  • 超时：保留部分证据并标记已覆盖范围，提供“缩小年份/法院/案由后重试”；重试形成新执行记录。

FR-05 统一任务中心

目的：让检索、解析和生成长任务的执行状态可理解、可恢复。

  • 触发：任何异步能力启动即创建任务；用户从案件或全局任务中心查看。
  • 展示：任务类型、所属案件、当前阶段、已用时、模型角色（如适用）、进度说明和可执行操作。
  • 状态：排队中、运行中、已完成、部分完成、失败、已取消；进度百分比仅在能真实计算时显示，否则显示阶段而不伪造百分比。
  • 取消：仅排队中/运行中可操作，需确认；已经产生的部分结果保留并标为部分完成或已取消，不保证底层计算立即停止。
  • 重试：失败、部分完成、已取消任务可重试；默认沿用输入快照，用户可修改范围。每次重试生成新的执行记录。
  • 异常：服务重启或页面关闭后重新打开，任务记录仍存在；无法确认最终状态时显示“状态待恢复”，不得直接标记成功。

FR-06 证据查看与研究摘要

目的：把检索证据转化为可编辑、可核验的研究草稿。

  • 触发：用户在检索结果中选择证据并生成摘要，或从空白研究页手动编写。
  • 处理：摘要引用只能指向本次案件内已选择的证据或材料；模型可组织语言，但引用标识必须对应真实证据。
  • 展示：检索证据与模型归纳采用不同视觉标识；点击引用在旁边打开原文，不高亮不存在的来源。
  • 编辑：用户可修改正文、删除引用、添加说明；删除证据时提示哪些摘要引用会失效。
  • 确认：“确认研究摘要”只表示用户已复核当前版本，不表示系统给出最终法律结论；确认后仍可通过新版本继续修改。
  • 异常：生成失败不丢失已选证据和已有正文；引用缺失或校验失败时阻止“已确认”状态，直到用户处理。

FR-07 保存、导出与交付版本

目的：把人工确认的研究内容变成可追溯、可下载的案件成果。

  • 触发：用户保存研究摘要或点击导出；P0 支持 Markdown 和 DOCX。
  • 处理：导出时冻结正文、引用和来源清单，记录任务、实际模型、时间和校验结果。
  • 校验：对正文中可识别的案号、日期、金额和引用执行现有交付检查；失败项必须列出具体位置。
  • 结果：成功后生成不可变交付版本和下载入口；正文后续修改不会改动旧文件。
  • 异常：校验失败默认不进入正式交付列表，用户可返回修正或明确选择“保留问题并导出草稿”，草稿文件和列表均需醒目标记。

08 P1–P3 需求

P1 完整法律工作台

模块必要产品行为与 P0 的共享规则
合同审查上传合同、选择审查立场与重点、展示风险条款/原文定位/修改建议；用户确认后导出审查版。合同是案件材料；审查是任务；风险意见是草稿；导出形成新版本。
诉讼文书生成选择文书类型，复用案件材料与证据，分节生成并允许逐节重写；事实字段缺失时先补充，不编造。沿用案号/日期/金额校验、引用溯源、人工确认和不可变交付。
证据评价按证据项展示证明目的、关联材料、风险与待补证事项。证据原文不可由模型改写；评价与原材料分离保存。
模型与路由设置按日常/质量/视觉角色配置模型；显示当前实际模型与换模影响；长任务执行中禁止无提示换模。历史任务保留实际模型快照，设置变化不重写历史。
知识与诊断显示知识库范围、更新状态、失败文件和服务日志；重建等危险操作需明确授权与维护窗口。诊断不暴露密钥；维护操作写入审计。

P2 安装、更新与恢复

  • 安装流程区分程序目录和用户数据目录，首次启动执行环境检查并给出可操作的修复说明。
  • 更新前验证程序、配置、模型与知识数据兼容性；用户案件和交付不参与覆盖安装。
  • 配置迁移失败时保留原配置并停止启动，不允许以默认配置静默覆盖。
  • 备份包含案件、任务、证据、摘要、交付和必要配置；模型与大型知识库可独立备份。
  • 恢复前显示备份版本、时间和影响范围；恢复动作需要确认并记录审计。

P3 团队能力边界

团队版再定义组织、成员、案件所有者、协作者、只读者和审计员。未评审前，不把 P0 的单用户本地授权机制扩展成“多人共用同一账户”。

09 共享规则与异常

9.1 权限与数据边界

  • P0 所有案件对当前本机用户可见；没有“分享给他人”或公开发布动作。
  • 远程瘦客户端只是访问入口，案件与模型数据仍位于用户指定的 SLP 数据节点。
  • 诊断和日志界面默认隐藏密钥、完整鉴权头和敏感路径；导出诊断包前提示可能包含的信息。

9.2 引用与事实规则

  • 引用必须指向已保存的证据对象；证据不可用或定位缺失时明确提示，不能自动补造。
  • 模型生成的案号、条款、日期、金额不属于证据，只有回到真实来源后才可作为已核验事实。
  • “部分检索”“部分解析”“部分完成”都必须在研究页和导出物中保留范围说明。

9.3 取消、重试与并发

  • 同一案件可并行发起任务，但界面必须提示共享模型资源可能带来的排队；不允许一个任务无提示打断另一个模型的流式输出。
  • 重试总是产生新执行记录；旧证据和旧错误保持可查。
  • 重复点击提交在任务创建成功前只产生一个任务；网络回包未知时先查询任务状态，不直接再次生成。

9.4 保存与不可逆动作

  • 归档、取消、恢复备份、重建知识库等动作需要确认，并说明影响范围。
  • 交付版本不可变；任何修改通过新版本完成。P0 不提供永久删除案件，避免不可恢复的数据损失。

10 非功能要求

维度要求
隐私默认本地处理案件材料与检索结果；调用云端模型或外部检索前，明确标识数据离开本机的范围并提供可关闭设置。
可靠性单个检索源、模型或解析器故障不影响已有案件与交付读取；任务失败不得损坏已保存成果。
可升级性业务对象和状态保持稳定；程序、配置、模型和知识数据独立版本化；迁移可检查、可备份、可解释。
可观测性每个任务记录输入摘要、阶段、耗时、实际模型、错误与重试关系；用户能看到可理解的说明，详细诊断可另导出。
性能优先返回首阶段状态和部分结果，避免页面长时间无反馈。[TBD] 具体首屏、检索和解析时延目标在 MVP 基准后确定，不预设无依据数字。
可访问性核心流程可用键盘完成；状态不只依赖颜色；长原文、表格和引用面板适应常见桌面宽度。
